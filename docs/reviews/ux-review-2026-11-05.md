## 0. 一页结论

**判断：机制层完成度高，表达层和异常路径是短板。**

- **底层值得信任**：串行单进程、同包去重、真实进度计数、取消分级、失败不复位的语义、崩溃对账、环境变量白名单、危险操作统一确认容器——这些是很多同类工具做不到的。
- **但用户看到的东西经常说反话**：失败显示成 0、未覆盖显示成「未发现」、预览失败显示成「很干净」、诊断说「未发现问题」。**十处 P0 里有四处是「把未知/失败/未覆盖渲染成安全/健康」**，这是本产品最大的交互风险，直接违背它「包可见性与安全更新体验」的定位。
- **危险动作的闸门装了一半**：「有包依赖它」仍可确认卸载；「删除关联文件」不列将删什么；30 个包的全量更新结束写「成功 1」。骨架都对，校验与结果表达没接上。
- **批量与结果是一组系统性问题**：批量入口缺确认、队列只是计数、结果弹窗关掉后就再也找不到失败项、历史任务不可回看。
- **所有功能都在，但「每个功能都差最后一公里」**：98 条发现按 10 P0 / 40 P1 / 48 P2 分布（去重后约 95 条，A/E 三处重叠已合并）。

**如果只修五件事**：① 十处「假安全」全部改为「未知/未覆盖/失败」+ 覆盖率常驻（A-01/A-02/B-03/D-02/D-06/D-07）；② 批量变更前给范围确认，汇总按包计数（C-02/C-01）；③ 被依赖包卸载阻断、zap 列出删除明细（B-01/B-02）；④ 退出前确认运行中任务 + 关窗提示（E-01/C-06）；⑤ 诊断包脱敏/预览，与隐私声明对齐（D-01）。

## 1. 十个 P0（按用户影响排序）

### P0-01「暂无修复的漏洞」被仪表盘写成「本次扫描未发现」〔A-01〕
- **证据**：`DashboardView.swift:67-73` 的 `securityDetail` 用 `index.securityUpdates.isEmpty` 判「本次扫描未发现」；同一张卡的表头用 `report.affectedFormulaCount`（`DashboardView.swift:162-166`）。`PackageSnapshot.swift:201` 证明 `securityUpdates = outdated.filter(\.isSecurityUpdate)`、`:175` 的 `isSecurityUpdate = finding != nil`，即它是「有漏洞 ∧ 有可更新版本」的交集。全仓无「完整扫描不代表没有漏洞」之类的免责文案。
- **用户场景**：老用户早上扫一次，`libtiff` 有 CVE 但上游无修复 → 统计卡写「本次扫描未发现」，下方安全卡却写「1 个受影响包 · 0 个有修复」；用户据此判断今天不用更新。
- **期望**：PRD F11.1/F11.2、AGENTS 硬约束 8——任何位置都不写「无漏洞」，只写「本次扫描未发现」+ 覆盖率，并区分「修复可用/暂无修复」。
- **建议**：`securityDetail` 改用 `vulnReport.affectedFormulaCount` 与 `fixableFindingCount`；安全卡底部固定一行免责说明；`index.securityUpdates` 只用于更新页标记。

### P0-02 刷新/outdated 失败在仪表盘完全不可见，0 看起来像健康〔A-02〕
- **证据**：`DashboardView.swift:26-65` 只拼日期 + 版本 + `lastRefreshAt`，不读 `refreshError` / `outdatedRefreshError` / `indexSourceNote`。状态层已正确记录并回退缓存（`AppState.swift:485-505`，注释明确「A failed outdated read must never look like "0 updates"」），但这些错误只在 `UpdatesView.swift:123,134-139` 与 `InstalledView.swift:29-33` 显示。
- **用户场景**：代理坏了/断网，刷新失败 → 仪表盘「可更新 0」「更新索引 12 分钟前」，用户关窗，错过全部更新。
- **期望**：启动即看的页面必须暴露数据来源与失败；失败时数字显示「—」而不是 0。
- **建议**：仪表盘顶部按优先级渲染 warning 横幅（刷新失败 / 更新列表失败 / 正在显示缓存 · 时间），附「重试」；header 标注「缓存 · X 前」。

### P0-03 被依赖的包仍可直接确认卸载，主操作未阻断〔B-01〕
- **证据**：`Sheets.swift:58` 的 `isConfirmEnabled: !zap || zapConfirmation == package.name` 只校验 zap 输入，不检查 `dependents`；`:63-68` 只渲染一条 warning。卸载入口 `PackageDetailView.swift:163-164,600-604`、`InstalledView.swift:205` 的右键、批量面板 `Sheets.swift:108-110` 都不因反向依赖禁用。
- **用户场景**：用户删一个「看着没用」的库，详情里明确写「被 10 个包依赖」，但「卸载…」仍是可点的危险按钮，确认即执行。
- **期望**：PRD F3.3——「被依赖时先展示反向依赖并禁用主按钮；默认不提供 `--ignore-dependencies`」。
- **建议**：`dependents` 非空时禁用确认，改为「查看被依赖（N）→」跳转；批量面板先筛出有依赖的包并默认排除。

### P0-04「删除关联文件」强确认不列将删除什么〔B-02〕
- **证据**：`Sheets.swift:79-82` 全文只有一句「会一并移除应用数据、偏好设置等，不可恢复」；`:70` 只预览 `brew uninstall` 命令；没有共享文件、登录项、待删路径、体积、是否移除应用本体，也不提示可能触发系统授权。
- **用户场景**：用户勾选「同时删除关联文件」后只能靠想象判断会删除什么；若偏好目录里有共享数据，无法事先知道。
- **期望**：PRD F3.4 与流程 4 第 2/3 步——列出「体积、是否移除本体、共享文件、偏好、登录项」，默认焦点在取消。
- **建议**：勾选后展开明细区（应用本体路径 + 体积取 `detail.sizeBytes` + 三类风险清单 + 命令预览）；术语保持「删除关联文件」，界面不出现 `--zap`。

### P0-05 被 brew vulns 跳过的 formula 仍显示「本次扫描未发现该包的漏洞记录」〔B-03〕
- **证据**：`PackageDetailView.swift:342-350` 的 `noFindingText` 只区分 cask 与「report 存在」，formula 一律返回「未发现」；同一视图 `:359-361` 却显示「跳过 N 个包不在映射范围」，inspector `:566` 同一文案。
- **用户场景**：用户看一个不在 OSV 映射里的 formula，看到「未发现」而认为已检查且安全——恰是「未覆盖」被写成「已检查无问题」。
- **期望**：AGENTS 硬约束 8、PRD F11——任何位置不写「无漏洞」，未覆盖要明说。
- **建议**：`noFindingText` 增加 `report.skippedFormulae.contains(package.name)` 分支：「该包不在 brew vulns 的 OSV 映射范围，本次未覆盖」，并附覆盖率。

### P0-06 批次汇总按「任务数」而非包数统计：全量更新 30 包显示「成功 1」〔C-01〕
- **证据**：`AppState.swift:909-946` 把整个 `brew upgrade` 作为**一个** `ChangeTask` 入队（`:929-944`），`progressTargets` 才是逐包；`TaskQueueStore.swift:705-729` 的 `finishBatchIfComplete` 用 `batch.taskIDs`（任务）计数；`Sheets.swift:346-351` 直接渲染 `succeeded/failed/...`。
- **用户场景**：36 个可更新包点「全部更新」，进度面板 36 行逐个打勾，结束弹窗写「成功 1 / 失败 0 / 已跳过 3」——用户以为只成功了一个，或以为其余 35 个失败但未报告。
- **期望**：PRD §7.9 F4.3、§8 流程 3——「N 成功 / M 失败 / K 已跳过」的 N/M 是包数。
- **建议**：汇总按 `progressItems` 终态计数（succeeded/failed/cancelled/skipped），失败项取 progress 行 name + recordID；任务数只留内部。

### P0-07「全部更新 / 更新所选 / 更新安全项」单击即执行，无确认面板〔C-02〕
- **证据**：`UpdatesView.swift:105-108` 直接 `appState.upgradeAll()`；`:157-161` 直接 `upgradeVulnerable()`；`:304-309` 直接 `bulkUpgrade(entries:)`；`Sheets.swift` 无批量更新确认页，`ContentView.swift:44-69` 也没有对应 sheet。
- **用户场景**：想勾两个包，手滑点到工具栏「全部更新」（⌘⇧U 就在旁边），36 个包立即开始变更，没有预计影响、没有取消机会。
- **期望**：PRD §8 流程 3 步骤 2——确认面板列出包与数量；批量、长时、不可撤销操作先确认。
- **建议**：复用 `ConfirmSheetLayout` 新增 `BatchUpdateSheet`：数量 + 类型分组 + 「已锁定 K 个跳过」+ 默认焦点取消；`--vulnerable` 同页说明仅覆盖可更新交集。

### P0-08 诊断包内容与隐私声明相反，且无预览/脱敏〔D-01〕
- **证据**：`SettingsView.swift:330-332` 与 `AppState.swift:1667` 都声明「不含包列表、命令输出、用户名或代理凭据」；但 `AppState.swift:1628-1634` 写入 `prefix/cellar/cache/repository` 绝对路径（默认 `cache` 即 `~/Library/Caches/Homebrew`，含用户名），`:1651-1652` 原样写入注入环境变量（`BrewEnvironment.swift:63-67` 把 `proxyURL` 放进 `HTTPS_PROXY/ALL_PROXY`，`:100-104` 返回 `KEY=value` 不脱敏，可能含 `user:pass`），`:1664` 写入含包名的任务标题（如「安装 foo」）；导出无预览、无勾选。
- **用户场景**：用户按支持指引导出诊断发给他人或贴 issue，一并泄露主目录路径、代理凭据与最近安装的包。
- **期望**：PRD F13.6「导出前预览；默认不含包清单与路径用户名，需显式勾选」；AGENTS §5.9 导出前脱敏。
- **建议**：加预览与脱敏开关；默认把 `$HOME` 替换为 `~`、掩码代理凭据、任务标题降级为操作类型。

### P0-09 没有安全更新时，漏洞覆盖率整块消失，只剩「0 个安全更新」〔D-02〕
- **证据**：`UpdatesView.swift:238` 用 `if !securityEntries.isEmpty` 包住整个 `securityHeader`，覆盖率 / 部分覆盖 badge / 扫描时间都在其中（`:245-253`）；页面 header 只写「X 个可用更新 · Y 个安全更新」（`:85`）；维护页无扫描摘要（`MaintenanceView.swift:34-60`）。
- **用户场景**：只扫出「部分覆盖」的用户，在更新页确认自己是否安全，看到「0 个安全更新」且找不到任何覆盖率信息，误判安全。
- **期望**：PRD F11.1、ui-design §8——覆盖率与跳过原因必须**始终可见**，不随列表为空而消失。
- **建议**：覆盖率行移到页面级 header（与安全计数同一行）；维护页补安全摘要入口。

### P0-10 退出/关窗不提示仍在运行的变更任务〔E-01〕
- **证据**：`MyApp.swift:17-46` 无 `NSApplicationDelegateAdaptor`，全仓无 `applicationShouldTerminate` / `scenePhase` / `willClose`；菜单栏退出是裸调用 `NSApp.terminate(nil)`（`MenuBarView.swift:73-75`）。
- **用户场景**：`brew upgrade` 正在跑，用户 ⌘Q 去开会；App 立即退出，子进程因 `POSIX_SPAWN_SETSID` 独立会话继续执行。用户以为停了，实际仍在改系统状态。
- **期望**：PRD F6.1 边界——退出时有运行任务需确认；关窗转后台并提示。
- **建议**：加 `NSApplicationDelegateAdaptor`，`applicationShouldTerminate` 返回 `.terminateLater` 并弹「等待完成 / 取消任务并退出 / 保持运行」，默认不退出；菜单栏退出与 ⌘Q 共用逻辑。

## 2. 七个跨页系统性问题（真正需要「一起修」的部分）

### 2.1 诚实性断裂：未知 / 失败 / 未覆盖 → 被渲染成「安全 / 健康 / 通过」
这是全产品最严重的一条，横跨四个域、六处界面：`DashboardView.swift:67-73`（有漏洞无修复→「未发现」）、`UpdatesView.swift:238`（无安全更新→覆盖率消失）、`PackageDetailView.swift:342-350`（被跳过→「未发现」）、`DashboardView.swift:26-65`（刷新失败→0）、`MaintenanceView.swift:170-173`（doctor 忽略退出码→「未发现问题」）、`MaintenanceView.swift:219`（missing 非 0→「检查通过」）、`AppState.swift:1331-1343`（清理预览失败→「很干净」）。
**修法不是逐条改文案，而是把「状态 → 文案」收敛成一个受测的映射**：任何「无数据 / 拉取失败 / 部分覆盖 / 解析失败」不得复用「成功」的视觉（绿色、对勾、「未发现」）。建议加一个 `HealthState`/`CoverageState` 枚举驱动所有卡片的副标题与颜色。

### 2.2 批量变更：范围看不见、确认不存在、结果不可回看
`C-02`（批量更新无确认）、`B-01`（批量/单个卸载不校验依赖）、`B-02`（zap 不列明细）、`A-10`（仪表盘「全部更新」也是单击执行）、`C-10`（「已选 N 项」与实际入队集合不一致）、`B-13`（批量卸载混合类型无分组）。共同模式：**危险动作的确认容器已经写好（`Sheets.swift:5-41`），但批量入口绕过了它**。建议统一规则：凡「影响 >1 个包」或「不可恢复」，必须经 `ConfirmSheetLayout` 且面板首行是「将影响 N 个包」。

### 2.3 结果不可行动：弹窗一关，失败就消失
`C-01`（汇总数字错）、`C-05`（失败行无退出码/建议/重试）、`C-07`（历史任务不可回看，抽屉永远显示最新一条）、`B-10`（卸载失败只有 2.8s toast）、`A-07`（点任意最近任务都打开最新那条）、`E-14`（toast 单条覆盖、不可停留、无动作）。建议闭环：**每次变更在「结果对象」上留三个入口——查看日志（定位到该记录）、复制命令、重试**；失败 toast 常驻并可操作。

### 2.4 队列是一个数字，不是实体
`C-03`（取消当前任务后立刻跑下一个）、`C-04`（排队项不可见、不可单独取消）、`C-17`（新批次混入旧进度行）、`D-17`（安装入队后行内无「排队中」）。PRD F6.1 明确要求「队列可见、排队项可取消」。建议暴露只读 `pending` 列表 + `removePending(id)`，并在更新页/抽屉行内显示「排队中」。

### 2.5 选择集与导航状态漂移
`B-04`（筛选后「已选 5 项」但目标 0，出现「卸载 0 个包？」）、`C-10`、`E-11`（打开包详情后侧边栏无高亮）、`D-05`（代理 3 个输入框无「应用」按钮、只有回车的隐式生效）、`B-15`（页头摘要不随筛选变化）。建议：所有「选择 × 筛选/刷新」组合都在 `onChange` 里清理失效 id；持久状态要么即时保存要么显式「应用」。

### 2.6 键盘与无障碍系统性缺失

## 7. 需运行验证（静态评审无法定论，建议按此清单实机走一遍）

5. ⌘Q / 菜单栏退出时运行中的 brew 子进程是否存活（`POSIX_SPAWN_SETSID` 独立会话）。

10. 存在反向依赖时 `brew uninstall` 的真实行为（是否直接拒绝、首行错误形态）。
11. `brew uninstall --cask --zap` 是否输出待删路径/共享文件/登录项。

13. `brew cleanup -n` 的真实输出格式与退出码（解析器只认无前缀的 `Would remove:`）。
14. `brew bundle dump --file=<已存在文件>` 是否必须 `--force`。

16. `brew doctor` 输出是否全部以 `Warning:`/`Error:` 开头。
17. 搜索失败是否被归为 `.networkFailure`（离线降级文案依赖它）。
18. 通知授权在系统设置中变化后，设置页开关与实际状态是否一致。
19. 980/1024 窄窗布局与检查器收起行为；深色模式下各语义色对比度。
20. 探测耗时 >5s 时的体验（是否出现 0 值闪烁）。
