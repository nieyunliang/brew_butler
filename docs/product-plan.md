## 2. 一句话定位、背景与问题

**一句话定位**：Brewbutler 是 macOS 27+ 原生 Homebrew 可视化管理器——把「装了什么、能不能安全地更新、占了多少空间、谁依赖谁」变成一眼可见、可取消、可追溯的操作。

**背景**：

- Homebrew 是 macOS 事实上的包管理基础设施，但它是「一次性终端输出」：状态不沉淀、跨会话不可检索、错误靠滚动历史。
- 现有 GUI 多停留在「把 brew 命令变成按钮」；用户真正的焦虑在**判断**：敢不敢卸、批量更新会不会炸、有没有已知漏洞、清理会不会误删。
- brew 已具备支撑判断的能力（`info --json=v2`、`vulns --json`、`outdated --json=v2`、`services list --json`），但这些能力分散在命令、参数与文本输出里，没有以「可决策」的形式呈现。

**三个典型痛点场景**：

| 场景 | 现状 | 代价 | Brewbutler 的回应 |
| --- | --- | --- | --- |
| A. 批量更新翻车 | 终端一把 `brew upgrade`，输出刷屏、上下文丢失；某包失败后其余继续跑 | 有包处于半升级状态却无人知晓，回滚靠猜 | 串行队列 + 单包成功判定（退出码 + 版本复核）+ 成功/失败清单 + 失败只给诊断 |
| B. 不敢卸载、不敢清理 | 不清楚谁依赖它；cask 的关联文件删除可能删共享文件；清理影响不可预估 | 磁盘越用越满，或误删导致应用损坏 | 反向依赖前置检查、危险开关二次确认、清理先 dry-run 预览 |
| C. 安全状态不可见 | `brew vulns` 能查 OSV 漏洞，但需专门命令；本机 36 个包约 29.7s，且 23 个包因无 source URL 被跳过 | 带着已知漏洞长期运行，或误以为「没报错就是安全」 | 后台扫描 + 徽标 + **强制展示覆盖范围、跳过原因与时效**；扫描失败显示「未知」而非「安全」 |

## 3. 目标用户画像

| 画像 | 特征 | 核心需求 | 「成功」的定义 |
| --- | --- | --- | --- |
| P1 独立开发者 / 技术负责人（核心） | 每天用 brew，60–200 个 formula + 若干 cask，懂命令但没空维护 | 快速审阅更新、批量升级、失败可诊断、健康度可见 | 3 分钟内完成一次安全更新并知道结果 |
| P2 技术爱好者 / 多机用户 | 多台 Mac、会用 Brewfile 同步、喜欢尝鲜 cask | 导出/导入环境、发现新包、看懂依赖 | 换机时用 Brewfile 一次还原 |
| P3 轻技术用户（设计师、写作者） | 通过 cask 装应用，不写命令，formula 概念模糊 | 像应用商店一样装/卸，别让我碰终端 | 不打开终端也能装好一个应用 |

**非目标用户**：Linux/服务器用户（Linuxbrew、systemd 不在范围）；CI/自动化（不做 headless CLI）；企业私有 tap 治理与合规分发（v1 不做策略引擎）；只要「一键优化」且不关心过程的用户。

## 4. 竞品分析

| 产品 | 形态 | 优势 | 不足 | 可借鉴 |
| --- | --- | --- | --- | --- |
| Cakebrew | 开源 macOS GUI（AppKit） | 出现早、覆盖面广，列表/安装/卸载/更新基本齐 | 交互与视觉停留在旧范式；无漏洞/磁盘/健康度视角；活跃度需核验 | 「列表 + 详情」基础骨架 |
| Cork | SwiftUI 原生 GUI（作者 buresdv，仓库活跃） | 性能口碑好；菜单栏快速更新、依赖可视化、包标记 | 主线仍是「操作效率」，安全更新与磁盘治理不是核心叙事；授权模式需核验 | 菜单栏常驻 + 依赖可视化 + 分类标记 |
| Beak | ※ 本轮核验显示 yonaskolb/Beak 为 Swift 脚本 CLI，并非 brew 图形前端；若指同名 GUI 应用，形态与活跃度**需市场核验** | 无法确认 | 无法确认 | 暂不作为设计参照 |
| Applite | 开源 GUI，聚焦 cask，界面接近应用商店 | 分类、推荐、搜索的开箱体验好，把「不懂 brew 的人」照顾到位 | 明确不覆盖 formula（依赖/服务/清理均不涉及）；漏洞与磁盘视角弱 | 商店式发现页的信息组织与筛选文案 |
| brew CLI | 官方命令行 | 能力最全最新，所有数据的一手来源 | 无状态沉淀、无聚合视图、文本需人肉解析、参数记忆成本高 | 一切数据以 JSON 输出为准，GUI 只做呈现与编排 |

> 参考：[buresdv/Cork](https://github.com/buresdv/Cork)、[cork cask](https://formulae.brew.sh/cask/cork)、[yonaskolb/Beak](https://github.com/yonaskolb/Beak)、[Applite 介绍](https://www.appinn.com/applite-for-homebrew/)、[Homebrew 文档](https://docs.brew.sh)。不引用具体版本号。

**竞争结论**：存量 GUI 的差异点集中在「操作更快」，几乎没有产品把**安全更新（漏洞 + 更新 + 依赖影响）**当主线叙事，这是窗口；风险是 Cork 等正在向依赖可视化与菜单栏扩展，Brewbutler 必须用「漏洞可见性 + 更新成功率 + 诊断质量」建立纵深，而不是靠界面；不与 brew 拼命令覆盖度。

## 5. 产品目标与成功指标

**产品目标（v1.0）**：① 让「安全地更新」成为默认路径（串行、可取消、有诊断、不做危险自动化）；② 让「装了什么」成为可检索可解释的知识（元数据/依赖/路径/体积/风险一处可查）；③ 在不建后端、不要账号的前提下做到可信任、数据可自查。

| 指标 | 统计口径 | 目标值 | 数据来源 |
| --- | --- | --- | --- |
| Activation | 首启后完成引导并至少完成一次列表索引的会话占比 | ≥ 85% | L1 本地事件 |
| 首次价值时间 | 首启到第一个变更类任务成功完成 | P50 ≤ 3 min | L1 本地事件 |
| 周活更新采纳率 | 当周有可用更新的活跃用户中 7 天内完成过一次升级的比例 | ≥ 60% | L1 + L2 抽样 |
| 更新成功率 | 单包升级成功数 / 总升级数；成功 = 退出码 0 且版本复核通过 | ≥ 97% | L1 本地事件 |
| 变更任务失败率 | 失败任务 / 变更任务总数 | ≤ 5% | L1 本地事件 |
| 失败可诊断率 | 失败任务中能落到已知错误映射或展示关键错误行的比例 | ≥ 90% | L1 本地事件 |
| 取消及时率 | 取消请求到进程退出耗时 | P95 ≤ 3 s | L1 性能采样 |
| 漏洞覆盖度可见 | 完成扫描的会话中「覆盖度卡片可见」比例；含 checked/total、skipped、complete、时间戳 | 100% 展示 | L1 |
| 漏洞扫描耗时 | `brew vulns --json` 单次全量耗时（本机 36 包 ≈29.7s 基线） | P50 ≤ 60s（按包数线性外推） | L1 性能采样 |
| 崩溃率 | 崩溃会话 / 总会话 | < 0.5% | 本地崩溃收集（默认不上传） |
| 冷启动 | 到主界面可交互（骨架可见） | P95 ≤ 1.5 s | 本地性能采样 |
| NPS | 应用内 0–10 推荐意愿，7 天最多问一次，可跳过 | ≥ +30 | L2 内测 + 自愿提交 |

**无后端前提下如何度量**：**L1 本地层**（默认，永不上传）——指标全部本地计算，设置页「使用统计」可查看、导出、一键清除；**L2 内测层**（显式 opt-in）——邀请制 beta 用户签署同意后每 24h 上报最小事件集（仅枚举值、计数、耗时区间、错误码，不含包名/路径/主机名/命令输出）；**L3 渠道估算**——Cask 与 GitHub Releases 下载计数、用户自愿导出的诊断包用于校准偏差。若最终不做 L2（最保守选项），NPS、采纳率等置信度下降，须在版本说明标注「基于本地样本，非全量」（见 Q1）。

| 一级导航 | 快捷键 | 核心内容 | 主要动作 |
| --- | --- | --- | --- |
| 概览 | ⌘1 | Homebrew 健康度、可更新数、漏洞数、磁盘占用、服务状态、最近任务 | 跳转对应模块、发起检查 |
| 更新 | ⌘2 | 可更新列表、漏洞优先视图、批量/全部更新 | 单个/批量升级、pin、查看日志 |

| 服务 | ⌘4 | brew services 列表与状态 | 启动/停止/重启、查看日志入口 |
| 维护 | ⌘5 | 磁盘占用、清理预览、doctor 健康检查、依赖完整性、Brewfile | 清理、健康检查、导入导出 |

非一级入口（v2.0，2026-11-07）：**发现**（关键词搜索、分类浏览 P1、安装入口）由工具栏全局搜索（⌘F）的「在 Homebrew 中搜索」与 ⌘K 进入；**设置**（brew 路径、外观、通知、代理/镜像与环境、隐私、诊断导出）为原生设置窗口（⌘,）。功能范围不变。

**全局层**：**⌘K 命令面板**（跳页面、跳包、执行命令，危险命令二次确认）；**菜单栏常驻项**（可更新数 + 快捷打开，P1）；**包详情为二级视图**（三栏：导航 / 列表 / 右侧固定 inspector；主区 6 个 tab = 概览、安全、依赖、被依赖、文件、历史；inspector 固定展示操作、概要、健康、路径、被依赖与危险区。不新增一级导航）。完整快捷键以 UI 文档 §3/§4 为准，PRD 只定义 ⌘1–⌘5、⌘, 与 ⌘K。

**命名基线（供 UI 文档对齐）**：界面 zh-Hans 优先，formula / cask / tap / keg-only / Bottle / Brewfile 保留英文小写；状态词表 = 未安装 / 已安装 / 可更新 / 已是最新 / 已锁定 / 有已知漏洞 / 已废弃 / 扫描未知 / 部分覆盖；危险动作词 = 卸载、强制卸载、删除关联文件（对应 `--zap`，不直接展示参数串）。

### 7.1 启动与环境（F0）

| ID | P | 用户价值与交互要点 | brew 对应实现 | 边界与失败处理 |
| --- | --- | --- | --- | --- |

### 7.2 任务基础设施（F6）

| ID | P | 用户价值与交互要点 | brew 对应实现 | 边界与失败处理 |
| --- | --- | --- | --- | --- |
| F6.1 | P0 | 变更任务串行，避免 brew 锁冲突与状态混乱；队列可见、排队项可取消 | actor 串行队列，同一时刻仅 1 个变更进程 | 第二个任务显示「排队中」；关窗转后台并提示；退出时有运行任务需确认 |
| F6.2 | P0 | 实时日志：ANSI 剥离、进度行合并、错误行高亮；更新任务默认展示逐包进度（更新页并入主列表内联展示，其他页面在任务岛展开面板的进度页；任务岛在更新页只保留批次总进度），日志一键切换保留；**反馈不打断**：任务开始时任务岛只以折叠态出现、不自动展开，批次结束进入任务岛「结果」态、不弹模态汇总，有失败时结果常驻到用户查看；任务完成的系统通知只在 App 不在前台时发送 | `Process` + PTY，stdout/stderr 合并为单一有序流；进度只按实际完成数与 `==>` 阶段行展示（见 technical-notes §4.2） | PTY 失败回退 pipe 并提示「无进度信息」；巨量输出虚拟化 + 落盘；进度解析失败降级为不定态进度，不臆造百分比 |

## 8. 关键用户流程

**流程 1：首次启动引导**
引导共 3 步（v2.0.1，UX 方案 O-11）：①检测 Homebrew → ②隐私与安全 → ③完成。
1. 启动 → 第 1 步顶部一句欢迎语，同时探测 brew（3 个固定路径 + 登录 shell，5s 超时）。
2. 成功 → 展示路径与版本，运行轻量探测（`--version`、`--prefix`、缓存中的 `outdated`；不含全量漏洞扫描），**并在后台开始首次索引**（59 包 ≤2s），不再单独占一步等待。
3. 第 2 步隐私与安全：本地优先、无账号、危险操作二次确认、不代理密码。
4. 第 3 步完成：提示 ⌘K（命令面板）、⌘R（检查更新）；可勾选「现在运行一次安全扫描（约 30 秒）」，默认不勾选（扫描仍由用户触发）。关闭引导进入概览；索引尚未完成时概览显示载入占位，而不是 0 值。
异常支线：未检测到 brew → 安装指引页；检测到多个 brew → 让用户选择并记忆；brew 可执行但非 0 退出 → 进入流程 6。

**流程 2：发现并安装（cask）**
1. ⌘K 或进入发现页 → 搜索 → 结果列表（名称、描述、类型徽标）。
2. 选中 → inspector 预览（版本、体积、是否已安装）→ 点击安装 → 任务入队，日志流式。
3. 若触发系统授权弹窗 → 指引卡片说明需在系统弹窗中授权（不收集密码）。
4. 完成 → 徽标变已安装 → 「在 Finder 中显示」「打开应用」。
异常支线：网络失败 → 降级 `brew search`/`brew desc -s` 并提示数据可能过期；安装失败 → 日志 + 错误解释 + 复制命令；已安装 → 按钮转「已安装」并提供重装（高级）。

**流程 3：批量更新并处理失败**
1. 更新页加载 `outdated --json=v2` → 按漏洞优先、类型分组展示。
2. 勾选或全选 → 「更新选中」→ 确认面板列出包与数量。
3. 队列逐个执行（同一时刻 1 个），每包结束做三重校验：退出码、`outdated` 复核、版本比对。
4. 结束 → 「N 成功 / M 失败 / K 已跳过（已锁定）」+ 可展开诊断 + 重试/复制命令。
异常支线：中途取消 → 当前任务标记取消，其余保持排队，可选「暂停队列」；磁盘不足/权限错误（含 cache 不可写）→ 映射为针对性建议；失败不中断队列。

**流程 4：卸载 cask（含删除关联文件）**
1. 已安装 → 选中 cask → inspector「卸载」。
2. 确认面板：包名、体积、是否移除应用本体；「同时删除关联文件」默认关闭。
3. 打开开关 → 红色警示 + 输入包名确认 + 列出风险（共享文件、偏好、登录项）。
4. 执行 `brew uninstall --cask <token>`（可选 `--zap`）→ 完成提示「已删除文件不可恢复」。
异常支线：需要 sudo → 指引卡片，不代输密码；卸载失败 → 展示残留路径与手动清理建议；用户取消 → 不发命令。

**流程 5：服务启停**
1. 服务页加载 `brew services list --json` → 卡片显示名称、状态、用户、plist 路径。
2. 点击「停止」→ `brew services stop <name>` → 重新拉取 list 复查并提示「已停止且取消登录时自动启动」。
3. 需要仅本次运行 → 「仅运行一次」（`run`），文案明确不注册开机启动。
异常支线：需 sudo 的系统级服务 → 拒绝并给终端命令；进程存在但未注册 → 提示可能由其他方式启动；子命令缺失（版本差异）→ 能力探测后隐藏入口。

**流程 6：修复 brew 环境异常**
1. 概览或任务失败触发「运行健康检查」→ `brew doctor`（流式采集，可能 >30s）。
2. 按 Warning 分组为卡片；**cache/prefix 不可写统一归入「权限不足」错误态**，附修复指引。
3. 每张卡片给解释 + 「复制命令」+ 文档链接；Brewbutler 不代执行高危修复。
4. 用户终端执行后回来点「重新检查」→ 对比前后结果；判定 brew 自身损坏 → 给官方重装指引。
异常支线：退出码非 0 且输出无法解析 → 展示原文并保留复制；长时间无输出 → 心跳提示并允许取消。

## 10. 技术方案要点（架构决策，不含代码）

- **分层**：SwiftUI（Features）→ 领域服务（BrewService / UpdateService / VulnerabilityScanner / ServiceManager）→ 进程执行层（ProcessRunner）+ 数据层（SnapshotStore / LogStore）。UI 只消费 `@Observable` 状态对象，不直接触碰 `Process`。
- **进程执行层**：`Foundation.Process` + 伪终端（pty）获取进度与颜色；stdout/stderr 合并为单一有序流；统一行缓冲、ANSI 剥离、超时与分级取消；注入受控环境变量（F6.5）并在诊断包记录注入清单。
- **单一操作队列**：actor 串行队列承载全部变更类任务，状态机 `pending → running → cancelling → succeeded/failed/cancelled`；只读命令（info/outdated/services list/vulns）走独立限流并发通道，避免列表刷新被长任务饿死。
- **漏洞扫描服务**：独立后台 actor 执行 `brew vulns --json`；**退出码 1 视为「有发现」而非失败**，失败判定只看能否解析 JSON 与 stderr；结果按「已安装快照哈希 + 24h TTL」缓存；默认启动不扫，由用户触发或低频定时；覆盖度（checked/total、skipped 及原因、complete、时间戳）与 findings 一并落盘，UI 必须同时呈现。
- **数据模型与解码**：为 `info --json=v2`、`outdated --json=v2`、`vulns --json`、`list --versions --json` 分别定义 Codable 模型，字段全可选并带默认值以容忍版本增删；解码在后台 actor 完成；解析失败保留原始输出到诊断目录以便补 fixture。
- **快路径与降级**：已安装列表优先 `list --versions --json`（轻量）+ 缓存元数据，首次/刷新时用 `info --json=v2 --installed` 补齐；`jq` 缺失或命令失败自动回退，降级原因在设置-诊断中可见。
- **存储分工**：SwiftData 存包快照索引、体积缓存、任务历史元数据、漏洞结果索引；UserDefaults/AppStorage 存轻量偏好（brew 路径、外观、通知、遥测、代理）；日志与原始 JSON 以文件存于 Application Support，**不把大文本塞进数据库**。
- **探测与缓存**：brew 路径（固定候选 → 登录 shell → 手动）与能力位（版本、flag、`jq`）一起缓存，任一变化即失效全部派生缓存；formulae.brew.sh 用 ETag/Last-Modified（**需技术验证**是否返回）→ 304 复用，否则 TTL 24h + 磁盘缓存，离线用过期缓存并标注时点。
- **分发与签名（含「为什么不做 Mac App Store」论证）**：① App Sandbox 默认禁止执行沙盒外任意可执行文件，而 brew 是 Ruby 脚本并会派生 git/curl/clang/xcodebuild 等进程，无法穷举授权；② 沙盒容器文件系统无法写 `HOMEBREW_PREFIX`（/opt/homebrew）、Cellar、Caskroom 与 /Applications；③ cask 安装/卸载需要提权（sudo、系统授权弹窗、LaunchDaemons），沙盒 App 无法提权也不应代输密码；④ MAS 对「下载并执行代码 / 更新其他软件」类应用审核风险高（条款编号**需法务核验**）。结论：Developer ID + Hardened Runtime + 公证 + staple 直发，可选 Cask 分发（`brew install --cask brewbutler`），用 Sparkle 与官网/Cask 触达。
- **Sparkle 取舍**：Sparkle 2 直发自更新（EdDSA 签名 + HTTPS appcast）；**双轨冲突处理**：检测到本 App 由 Cask 安装（`brew list --cask` 命中）时禁用 Sparkle 自动更新并提示用 `brew upgrade --cask brewbutler`。
- **错误分类**：至少区分 `notFound`（命令/包不存在）、`permissionDenied`（cache/prefix 不可写、TCC、sudo 需求）、`networkFailure`（API/OSV 不可达）、`parseFailure`（输出结构变化）、`cancelled`、`brewFailure`（含退出码与关键行）；错误分类直接驱动 UI 修复指引。
- **测试策略**：把本机真实输出固化为 fixture（`info --json=v2 --installed` 59 包、`outdated --json=v2`、`services list --json` 的 `[]`、`vulns --json` 含 complete=false 与退出码 1、`search --desc` 文本、`cleanup -n` 文本、`doctor` 文本），通过 `ProcessRunner` 协议注入 FakeRunner 回放；关键路径快照测试；性能用 10k 合成 JSON 基准。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| brew 输出/JSON 结构随版本变化 | 解析失败、功能不可用 | 全字段可选模型 + 版本化 fixture 回放 + 能力探测降级 + 保留原始输出；发布前多版本回归 |
| 漏洞覆盖不全（本机 23/36 因无 source URL 被跳过）与耗时（36 包 ≈29.7s） | 用户误判「已安全」，或认为扫描卡死 | 强制展示覆盖度/跳过原因/complete/时间戳 + 「未知」态 + 后台可取消 + 缓存；大环境给进度与预计耗时 |
| `vulns` 有发现时退出码为 1 | 被误判为任务失败、误报错误 | 明确语义：退出码 1 = 有发现；失败判定基于能否解析 JSON 与 stderr；fixture 覆盖 |
| cask 需要 sudo 与系统授权 | 关键操作无法在 GUI 内完成 | 指引卡片 + 可复制命令 + 文档写明「已知限制」；不做密码代理 |
| 受限环境（cache/prefix 不可写）导致 `doctor`/`update` 报错 | 被误认为 App 故障 | 识别为「权限不足」独立错误态并给修复指引；只读模式兜底 |
| `jq` 缺失导致 `list --versions --json` 不可用 | 快路径失效 | 启动探测 `jq`；缺失时回退 info JSON 或文本并标注降级 |
| 性能：体积扫描与大列表 | 10k 包环境卡顿 | 骨架先出 + 增量后台计算 + 缓存 + 虚拟滚动；M3 压测门槛 |

## 14. 附录

### A. brew 命令能力矩阵（本机 Homebrew 7.0.10 验证；※ = 需技术验证）

风险等级：低 = 只读；中 = 可逆变更；高 = 可破坏系统状态或不可恢复。

| 命令 | JSON | 用途 | 风险 |
| --- | --- | --- | --- |
| `brew info --json=v2 --installed` | 是 | 已安装包完整元数据（主数据源，59 包 0.41s） | 低 |
| `brew info --json=v2 <name>` | 是 | 未安装包预览（稳定性※） | 低 |
| `brew list --versions --json` | 是（依赖 `jq`） | 轻量版本/链接/pin（name/versions/linked_version/optlinked_version/pinned_version） | 低 |
| `brew outdated --json=v2` | 是 | 可更新列表（formula + cask） | 低 |
| `brew outdated --vulnerable` | ※ | 漏洞快速子集（仅 outdated 交集） | 低 |
| `brew vulns --json` | 是 | OSV.dev 全量漏洞扫描（findings/skipped_formulae/checked/complete；**有发现时退出码可能为 1**） | 低 |
| `brew vulns`（`--severity`、`--fix-available`、`--fix-type`、`--list-skipped`、`--brewfile`、`--deps`） | 部分 | 严重度与修复可用性过滤、跳过原因 | 低 |
| `brew services list --json` | 是 | 服务状态（无服务返回 `[]`） | 低 |
| `brew services start/stop/restart/run/kill` | 否 | 服务控制 | 中 |
| `brew search`（`--desc`/`--formula`/`--cask`）、`brew desc -s` | **否** | 发现页搜索（文本解析；`desc` 首次建缓存较慢） | 低 |
| `brew install` / `--cask` | 否 | 安装 | 中 |
| `brew uninstall` / `--zap` / `--ignore-dependencies` | 否 | 卸载 | 中 / 高 |
| `brew upgrade`（`--dry-run`、`--no-ask`、`--vulnerable`、`--formula`、`--cask`、`--greedy`） | 否 | 升级 | 中 |
| `brew reinstall` / `--force` | 否 | 重装/覆盖 | 中 / 高 |
| `brew pin` / `unpin` | 否 | 锁定/解锁 | 中 |
| `brew update` / `update-if-needed` | 否 | 更新索引（后者按需） | 中 / 低 |
| `brew cleanup`（`-n`、`--scrub`、`--prune`）、`brew autoremove`（`--dry-run`） | 否 | 清理旧版本/缓存/未使用依赖 | 中 / 高（autoremove） |

### B. 已确认的环境变量（用于输出确定性与副作用抑制）

- **默认注入（解析与隐私）**：`HOMEBREW_NO_COLOR`、`HOMEBREW_NO_EMOJI`、`HOMEBREW_NO_ENV_HINTS`、`HOMEBREW_NO_ANALYTICS`；只读命令额外注入 `HOMEBREW_NO_AUTO_UPDATE`（避免隐式更新副作用）。
- **可选（设置中开启）**：`HOMEBREW_NO_INSTALL_CLEANUP`（安装后不自动清理）。
- **默认不注入（会改变 brew 行为，语义※）**：`HOMEBREW_NO_SUDO`、`HOMEBREW_NO_SANDBOX_CASK`、`HOMEBREW_NO_APP_MANAGEMENT_PERMISSIONS_PROMPT`；仅在高级设置中显式开启，且需说明影响。
